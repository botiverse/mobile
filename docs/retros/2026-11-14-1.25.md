# 1.25 发版复盘（2026-11-14）

Release issue: #4731 (`Release 1.25.0`). Procedure: `docs/mobile-release-sop.md`.

## Summary (English)

The 1.25.0 train shipped, but hit platform limits that the previous release
already hinted at:

- The iOS release link ran out of Kotlin/Native heap (12g); raising it to 20g
  (#4744, release branch #4745) changed the release branch, so both platforms
  were rebuilt as a new candidate.
- The IPA was 106 MB, over Cloudflare's 100 MB per-request limit. Hands CLI
  0.5.49 added direct upload for iOS and 0.5.50 for all uploads.
- Google Play submission was blocked by "changes in review": the 1.24.0
  production release, not the data-safety form as assumed. Hands' review-status
  read had been failing (403) for five days unnoticed. 1.25 went to production
  with the new withdraw-and-replace (`--cancel-in-review`).
- QA install now grants runtime permissions (`-g`, #4746); the Android update
  path is tested automatically on GitHub Actions (#4750), with scripted
  release-build login (#4760, #4763).
- That update e2e caught a bug present since 1.18: cold start deleted every
  draft (fix #4762, ships in 1.26). The iOS vphone smoke caught broken image
  paste (present since 1.24, fix #4779, 1.26).
- User feedback exposed parsers silently dropping unknown server data; audited
  and fixed with a rule and contract tests (#4769). Realtime moves to the common
  Kotlin client (#4776, #4778, iOS behind a flag).

Lessons: test state across process restart and update; silent failure is the
most expensive kind; a new test must first fail without its fix; treat platform
limits (package size, link memory) as known risks and check their trend before
each release; write delegated authority into the SOP and the release issue;
script repeated manual checks; keep fixed QA fixtures. The SOP changes are in
`docs/mobile-release-sop.md` (release authorization, pre-release trend check,
Hands CLI version, update e2e, Play `--cancel-in-review`).

## 发生了什么
- iOS 正式包内存不够（Kotlin/Native 链接 12g OOM）→ 调到 20g（#4744，release 分支 #4745）→ 改了 release 分支 = 新候选，安卓也重出包。
- iOS 包 106MB 超过 Cloudflare 100MB 单请求上限 → Hands CLI 改直传（hands-cli 0.5.49），之后所有上传直传（0.5.50/0.5.51）。
- Play 提交被"有改动在审"挡住，一直以为是数据安全表单，其实是 1.24.0 正式版在审；Hands 读审核状态 403 已停 5 天没人发现。最后用新加的"撤回并替换"（`--cancel-in-review`）直接提 1.25 正式版。
- 冒烟第一条卡在测试环境（通知权限弹框让首页没加载）→ 测试装包加 -g（#4746）。
- 正式包升级测试在模拟器上卡在浏览器回跳 → 做了 GitHub Actions 自动升级测试（#4750）+ 正式包自动登录脚本（#4760、#4763）。
- 自动升级测试抓到一个 1.18 起就有的严重 bug：冷启动删光所有草稿（#4762；产品负责人决定跟 1.26，不出 1.25.1）。
- iOS vphone 冒烟抓到图片粘贴失效（1.24 就有，不是回归），修复跟 1.26（#4779）。
- 当天用户反馈暴露一类共性问题：解析层遇到不认识的数据静默丢弃（已保存里的任务、原始日志空白、Slack 消息离线丢失等），做了全量审计 + 规则 + 契约测试（#4769）。
- 实时连接统一到 common Kotlin 客户端（#4776、#4778，iOS 开关灰度），跟 1.26。

## 经验
1. **测试要测"重启之后"。** 草稿 bug 存在了 7 个版本，单测和截图测试都只测同一进程内。升级 e2e 的"草稿还在"断言一次就抓到。以后关键本地状态（草稿、设置、登录）都要有"杀进程/升级后还在"的断言。
2. **静默失败是最贵的 bug。** 已保存任务、原始日志、Hands 403、Play 审核通知，都是"失败了但看起来像没数据/没变化"。规则：解析不丢数据、丢必须留痕；自动通知自己失效要报警（Hands 已加）。
3. **测试只覆盖它造出来的情况。** iOS 粘贴测试的输入框从不重启输入会话，所以永远绿；vphone 接硬件键盘一测就红。新测试要先在不带修复时证明会红。
4. **发版前把平台限制当成已知风险。** 包体积接近 100MB（1.24 是 100.98MB）、iOS 链接内存接近上限（1.24 链接 36 分钟），都是前一版就能看出的信号。发版 SOP 加：包体积和链接时长/内存的趋势检查。
5. **授权要写在 SOP 和工单里。** 产品负责人已授权移动端 DRI 做发版决定，但 SOP 和 #4731 还写着"需要产品负责人的 go"，子代理照章停下。已在 #4731 记录授权；SOP 要更新。
6. **重复手工的验证都脚本化。** 升级测试（已做成 GitHub Actions）、正式包登录（脚本）、iOS 冒烟（iOS QA 录成 vphone 回放脚本，进行中）。
7. **测试数据不要靠临时造。** 成员描述验证卡在测试服没有合适数据。需要一份固定的 QA 夹具（带描述的人和 agent、离线电脑、可用的助理）。
