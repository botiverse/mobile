# OHOS 证据分级与模拟器边界

Owner: Ark · Verified at: 2026-10-18 · Status: current

OHOS 验证报告的口径纪律：每个用例给一个明确的终态，不推断、不外推、不省略。通用视觉证据分级见 `mobile-visual-evidence-ceiling.md`，发布载体对账见 `release-provenance-containment.md`；本文是 OHOS 侧的具体边界。

## 1. 六格口径

每个用例落在且只落在一格（沿用 `docs/android-release-sop.md` §5.2 的断言终态，另加一个时间维度变体）：

| 终态 | 含义 | OHOS 例子 |
|---|---|---|
| **PASS** | 断言在绑定了身份链（源码 SHA + 包 SHA + 目标 serial/API）的载体上实际跑过并通过 | API24 模拟器上，11400008 包登录 staging、冷启动会话保留 |
| **FAIL** | 跑过且断言失败 | 显式旧版本号（1.12.0）被版本门拒绝——对「拒绝」断言是 PASS，对「接受」断言就是 FAIL，写清断言方向 |
| **NOT RUN** | 该用例本轮没执行（没排进、没座位、被跳过），如实列出 | 「下载中清除」busy guard：两次尝试里下载都在导航到存储页前完成，用例没跑成 |
| **NOT PROVIDED** | 执行所需的外部输入没人提供 | 物理真机执行席、AppGallery 邀请链接、某个 QA 账号 |
| **NOT COVERED** | 载体/设备**结构上**跑不了该用例，写明结构原因 | 见第 3 节 |
| **未判定** | 有观察但证据不够下结论 | 浏览器白屏换实例后自愈：现象记录了，根因未判定 |

变体 **NOT RUN·不可再得**：当时没跑，且证据窗口已永久关闭（候选包已被 supersede、一次性实例已拆除），不能再补。把它和普通的 NOT RUN 分开写，因为「可以补跑」和「永远补不了」对决策的含义不同。

纪律：格子不够的用例**留在表里标终态**，不要从表里删掉；推断出的 PASS 不是 PASS。

## 2. 物理真机 NOT RUN 边界

当前没有 OHOS 物理真机执行席。由此：

- 一切真机专属行为（真实安装链路、真机渲染/触控时序、射频与网络切换、具体机型）一律标 **NOT RUN / NOT PROVIDED**，并写明缺的是座位。
- **模拟器 PASS 不外推物理。** 模拟器上装得上、跑得通，不证明真机装得上、跑得通。
- 签名 profile 是 release/app_gallery 类型也只证明签名身份，不证明物理 USB 可装。
- 反过来也成立：模拟器上的失败不自动等于真机失败——例如某构建在模拟器上切换中文 UI 不生效（选择持久化但界面仍英文），标 NOT RUN/未判定并注明「疑似构建既有限制」，而不是直接断言真机也不生效。

## 3. 模拟器上结构性证不了的东西

这些不是「还没做」，是当前手段在结构上够不到，标 NOT COVERED 并用其他层兜底：

- **已安装字节级回读**：`hdc shell` 是 uid=2000，无权读已安装应用的 HAP 字节。所以「装上去的字节 == 下载的字节」在模拟器上证不了；替代链是：安装前对包做 SHA-256 对账 + 安装后 `bm dump` 回读 versionCode/versionName。
- **应用沙箱写入**：shell 无法写应用沙箱，构造不了「缓存目录里有多层嵌套子目录」这类前置状态。兜底是源码审查确认递归清除路径 + LocalUnit 断言覆盖。
- **仅计量的目录**：如 crashes 目录设计上只计量不清除，且设备侧不可读——「不清除」无法从设备侧正面验证，只能确认它没被计入可清除集合。
- **secret-store 字节级擦除**：会话清除的证据层级是 UI/冷重启（登录页回来、旧会话不复活）。字节级 secure-store 检查在模拟器上做不到，报告里写「UI/重启级证据」，不升级措辞。
- **HDC 连接层权限边界**：模拟器上 hdc 可用不代表真机上同样的命令可用；真机侧权限模型不同，相关用例在未拿到真机前全部 NOT RUN。

## 4. 写回执的最小骨架

一份 OHOS 运行时回执至少绑定：源码 SHA / 包名与 versionName+versionCode / 包 SHA-256 / 目标 serial + API + software 版本 / 每个用例的六格终态 / 未跑用例的原因归属。Gradle/Hvigor 构建成功本身不是设备证据；只有模拟器 PASS 时，发布结论里物理格子保持 NOT RUN。
