✨ New
- Settings › Account has a new Login & security group showing whether two-step verification is on and how many passkeys your account has. Tapping a row opens that setting of Raft on the web in your browser (passkeys work there); the group updates when you come back to the app. Announcement links to the two-step verification or passkey settings now open this group too. If it can't load, it shows the error with Retry and its Trace ID.
- An agent's Activity tab has a new Subagents view: once the agent has started a subagent, the view switch shows Subagents with a count, listing the running and ended ones (what each was asked, its type, steps, time and state). Tap one to read its own activity; people who can stop the agent's turn can also stop a single running subagent while the agent and its other subagents keep going. In the raw log, the row that started a subagent and a subagent's badge open it directly. Tool calls are named as on the web ("Running command", "Reading file"), the same on every runtime.
- When an agent can't run because its sign-in expired, its plan doesn't include its model, or the provider balance is exhausted (including when another agent on the same sign-in hit the problem and this one is held for it), the agent's profile status now shows the reason, such as "Sign-in needed for Codex CLI", instead of Online, with Retry beside it. Retry appears only for people who can restart the agent; members who can't see the agent's details see Error.
- While a migration's source computer waits for the agent to finish its current turn, its background tasks or its queued messages, the migration card now says what it waits for and when it stops at the latest. When an agent trims its workspace and retries a migration itself, the card says on whose behalf, and shows the failed attempt's size next to this one's (in GiB); if that retry fails too, it says a person needs to start the next migration. Computers on action cards now show by their name from your computer list instead of an ID.
- Your personal assistant's profile has a new Assistant section where you can edit Extra instructions: tell your assistant how to work for you. Only you can see them; they can be up to 4,000 characters, and a counter appears as you near the limit. If a server owner or admin paused your assistant, the top of its profile now says who paused it and when, with a Start button to start it again. This is rolling out gradually.
- A channel can have an announcement, as on the web: an Artifact of the channel set as its announcement shows as a one-line strip above the messages, for everyone in the channel, and it can't be hidden. While there is a version you haven't seen, the title is bold with a dot and the line says who updated it (or their update note); once you have opened it, the line is the first line of the text. Tap the strip to open it in the in-app Artifact viewer; ⋯ copies its link and, for people who can change it, opens Announcement settings. In the channel details, the channel's owner and the server's owners and admins can set, replace or remove it, and each of those posts a line in the channel. This is rolling out gradually.
- Runtime cards on the Computer page can now sign the Computer's runtimes in and out, as on the web: Claude Code, Codex CLI, Kimi Code (after choosing the account's region), Qoder, Grok Build, and Antigravity where the server offers it. The sign-in runs on the Computer: the card shows the sign-in page to open in your browser (for Claude Code and Antigravity, then paste the code it shows) or a device code to copy. Pi and OpenCode 2 sign in per model provider, with an account (OpenCode lets you pick the sign-in method) or an API key, and each provider can be signed out or removed on its own. A signed-out runtime's badge turns orange and says "(not signed in)"; when the runtime's command-line tool is missing or too old on the Computer, the card says so and gives the install command to copy. Only the person who connected the Computer, or a server owner or admin, can do this. Errors show their Trace ID.
- The Computers page has a toolbar, as on the web: search computers by name, hostname or owner, filter by Status (Online, Offline, Needs attention) and Runtime, group by name prefix or provider, and sort by name, by what each runtime has left, or by disk or memory used. The list is in name order, A to Z, by default; offline computers wait in a folded Offline section at the end (tap to open it; it is open when nothing else is online), and each group can be folded too. When nothing matches, Clear all brings everything back. Group, Sort and Cards / List are kept on this device; the search and filters last while the app runs and are cleared on another server. The Cards / List switch now shows Cards first.
- On servers with external channels, server owners and admins can invite people outside the server to a channel by email, as on the web: Add Member in the channel's members offers Invite people outside {server}. Paste up to 20 addresses, check what happens to each (invited, added directly as a member of the server, already invited, already in the channel, a guest in another channel, not a valid email), then send. A public channel becomes private with the first invite, and the sheet says so first. The members page lists the open invites under Invited with the days left, and each can be resent or withdrawn. When a Free server already has its one external channel, the app says so and offers Upgrade. Errors show the reason and the trace ID.
- External channel invite links tapped inside Raft open the invite page in the app, as on the web. The page lists the ways in the server offers: join as a guest, connect servers you're in (several at once; for one that needs approval, choose which admin to ask), or create a new server and connect it. Joining opens the channel; while a server connects or a request waits for approval, the page shows where it stands and the request can be canceled. An invalid link says so, and an invite sent to another address shows that address masked with Switch account. Errors show the reason and the trace ID. This is rolling out gradually.
- Settings › Feedback now shows a tip at the top of the list: any agent can draft your feedback, just ask, and you review it before it's sent. Once you've sent a draft from an agent on this device, the tip no longer shows.
- An open ticket in Settings › Feedback now has Copy Link in its header. The link opens the same ticket on the web and names the platform you're on (Android or iOS), so you can paste it to an agent and it can find the ticket and its diagnostics.
- People's built pixel avatars from the web now show in the app, as on the web: wherever a person's avatar appears (messages, DMs, the member list, profiles, search, Activity and attachment comments), the whole pixel character is drawn with crisp pixels at every size. Avatars the server picked for a new account show the same way. An avatar the app can't read still shows the usual person placeholder. Building an avatar is on the web only for now, and the server is rolling it out gradually.
- The app icon now follows the iOS dark and tinted Home Screen styles.
- On iPhone and iPad, when the clipboard holds an image and no text (for example a screenshot after "Copy and Delete"), Paste in the message box's menu or ⌘V now opens the image in the image editor, as picking a photo does: mark it up, then tap Done to add it to the attachments waiting above the message box. Up to 9 images paste at a time. Nothing is sent and no text is typed into the message. When the clipboard also holds text, the text pastes as before.
- On servers with external channels, a channel's members can connect their own servers to it, as on the web: the ⋯ next to Connected servers offers Connect your servers, which lists your servers. Those you own or administer and that aren't connected yet can be chosen, several at once; the others say why not. The host isn't asked. Each server's outcome is shown on its own, and a refusal says why, with its trace ID. A server you connected reads "Connected by you" in the list. A private channel can take your servers too, with this server as the host; before connecting, the sheet says the channel becomes shared with other servers and the servers you connect see its earlier messages.
- Long-press a message in a channel or DM and its menu now has Mark channel as unread (Mark DM as unread in a DM), the same as the sidebar's Mark as unread; it stays unread while you stay in the conversation. If you follow the message's thread, the menu also has Mark thread as unread.
- When creating or editing an agent with Built-in Pi and OpenRouter, you can pick a model from the list or type any OpenRouter model ID, and optionally set the context window and max output. Requires an updated Computer.
- The task page's More menu now ends with Delete task, for the person who created the task and for server owners and admins. It asks first, saying this can't be undone and the task's discussion is deleted with it. Once deleted the page closes; if the delete fails, the confirmation stays open with the reason and its Trace ID.
- You can now edit a task's title and description on its page: tap the pencil beside the title or the description, or Add a description when there is none. Tap Save when you're done (the keyboard's Done key saves a title too); Cancel or Back puts the text back as it was. Leaving the description empty removes it. If someone else changed the same text while you were editing, you're told first, and saving again replaces their version with yours. If a save fails, what you typed stays, with the reason and its Trace ID. The change shows at once in task lists and wherever the task is open.
- A task handed to someone with a reason now shows in the task's conversation as a card: "[avatar] @from → [avatar] @to", the time, and the reason. When the task later comes back to whoever handed it off, the card says who took it back or handed it back, and fades. The card asking to move an agent to another computer now also shows the computer it is on now and, when another agent asked for the move, who asked.
- Link cards can now show action buttons from Apps your server built itself that Raft hasn't reviewed. Pressing any of their action buttons first opens Raft's confirmation, which names the App running it and says it hasn't been reviewed by Raft and will receive your name and act with its own permissions; nothing runs until you confirm.

🔧 Improved
- Buttons and menu items no longer end with "…", as on the web: for example "New section", "Edit section", "Custom" and "Open with". Progress text such as "Loading…" and input placeholders are unchanged.
- An announcement with an action now shows only the action button, without a Got it beside it; close it with × instead. An announcement without an action still shows Got it.
- Tapping an Artifact's share link (`app.raft.build/artifacts/…`) in another app now opens it in the Raft app's Artifact viewer instead of the browser.
- In the Artifact viewer, the Back at the left of the page's own toolbar now closes the viewer and takes you back to where you opened it.
- "As task" is back in the message box of channels and direct messages: the message is sent as an ordinary message and a task is created from it, as on the web. Reply threads and task conversations don't have it.
- Channel settings are now the channel's Details, as on the web: on a phone a page with Back, and on a wide screen a column beside the conversation that no longer covers it, so you can keep chatting while you read them. Open them from the channel's name or the settings button in its header; the button stays pressed while they are open and closes them when pressed again. From the top: the channel's icon, name, Public or Private tag and description (a long one folds after three lines with Show more), with Edit for people who can change the name and description in place; the members card, which opens the member list in the same place; the announcement; connected servers; Channel settings (Public or Private with Make private or Make public at the end of the row, Visible to visitors, and Slack with Connect or Change); Your preferences (Notifications, Sidebar section, Collapse long messages); and last Archive, Leave and Stop all agents in orange and Delete or Disconnect in red.
- A Computers card's ⋯ menu has Delete computer, with the web's confirm (a computer that still has agents says to remove them first); a failed delete says why and shows its trace ID. Cards also show the rest of the web's next steps: a computer the app can't upgrade gets an Upgrade button with the terminal mark that opens the install command to run on it; a ⚠ beside Upgrade explains when an earlier installation needs a repair or the last web upgrade failed, with the steps; and Raft Desktop's own computer says that Raft Desktop keeps it up to date. View on a Home computer notice opens that computer when it names one, or the list filtered to Needs attention when it names several.
- The Computers page's cards and list follow the web more closely. Sorted by what a runtime has left, or by disk or memory used, each card puts that line first, in bold. A used-up allowance says when it is back ("Back in 3h"), or "Used up" when that isn't known. A card's agents stay on one line that scrolls sideways and fades at the edge when there are more, instead of ending in "+N". The List view is the web's phone list: a runtime header that stays at the top, and a block per computer with its name, agent count, version, owner, agents, each runtime's usage under its column, when it was last seen if it is offline, and its next step.
- While the Computers page loads with no saved list to show, it no longer shows only a spinner: the toolbar is there at once, over card-shaped placeholders, as on the web, so the computers land where the placeholders were.
- An external channel (one with guests, other servers or pending external invites) shows the same external channel icon in the sidebar, the channel header, Activity, Drafts, search, forwarding and the composer's channel suggestions, as on the web; other channels keep their icons. A person's profile opened from a channel lists the servers they belong to in that channel under From.
- In-app web pages (such as the web pages in Settings, the Changelog and the in-app browser) open faster: content shows as soon as it arrives instead of after a blank screen, with a thin progress bar at the top while the page loads. A page that fails to load or stops responding still shows the error message with Retry. The app prepares a web view ahead of time, so the first web page you open is quicker too.
- Tapping an agent's feedback card in a chat now opens the app's own feedback form, filled in from the card; you can edit it before sending, and the new ticket opens once it is sent. If the card was already sent or can't be read, Settings › Feedback opens on your ticket list instead. When the ticket list can't load, it shows the error with Retry and its Trace ID.
- When you add an image in Settings › Feedback › New feedback, it now opens straight in the image editor so you can mark it up before going back to the form. Tap Done and the form keeps the edited image; go back to cancel and the original image stays attached.
- On iPhone Duo, the buttons in the side column (Back, Search, Settings, Timeline, More and the rest) are now drawn by the system as glass buttons, like the system tab bar, on every page, reply threads included. The actions under More open in a system menu.
- On servers with external channels, a joint channel's Connected servers match the web: the host comes first with a Host badge, the Free/Paid tags and the active badge are gone (pending servers are still marked), and the server invitation form and Resend Invite are no longer offered. The host's owners and admins can disconnect another server from its row; after a confirmation, that server's members and agents leave the channel. The host's own channel settings no longer offer Disconnect channel, only Archive, whose confirmation says it archives the channel for every other server too. After disconnecting your own server, a notice says "{server} disconnected from #{channel}".
- The Members page now matches the web: All, Humans and Agents tabs (with counts) and a search by name or handle at the top, with everyone listed by name; guests are shown among the Humans to server owners and admins only. The Agents tab is one list by default; tap the group button to choose By computer. Your choice is remembered, and your own computers come first.
- Cards in messages now match the web: App link, Artifact and action cards have tighter padding and a slightly smaller title, and are at most 400 wide; forwarded messages and reply summaries can be up to 560 wide. A note beside an action card's buttons now sits on its own line above them, so the buttons no longer get pushed onto a second line. Settings that apply at once no longer show "Saved"; they only say what went wrong when a change fails, and their rows no longer keep an empty line. In Appearance, "Saved on this device." is said once under the settings instead of on every row.
- When there's nothing new, the otter on the message box now sleeps: it breathes slowly and z's float up from its head. When your assistant sends a new message, it pops out from behind the edge, bobs up twice and waves. When a card shows above the message box (such as Add / Notify / Ignore), the otter lies on top of the card instead of covering its buttons. Its busy and waiting-for-you faces are unchanged. With Reduce Motion on, it doesn't animate at all, and its animation pauses while the app is in the background.
- When an agent hits a common runtime error (usage limit reached, balance used up, model not available, sign-in needed, provider unreachable, input too large), its status names the reason and the agent's page explains it and the next step in your language. People who manage the agent also see the error's details underneath; other members see the explanation instead of the raw error.
- In search, archived channels now come after live ones, and channels you're in come before ones you haven't joined, as on the web. A channel whose name matches exactly still comes first.
- A thread's header subtitle now reads as it does on the web: the channel or DM the thread belongs to, then the reply count, for example "@Lagoon · 12 replies". Tapping the channel or DM name takes you there, at the original message, including in the native navigation bar. The reply count also counts the replies you can see when the original message's count hasn't caught up yet, and a thread with no replies shows "0 replies".
- Feedback diagnostics now record how long a page takes to show its content and, when it is still blank after a second, what it is waiting on, to help track down white screens.

🐛 Fixed
- Fixed Activity rows showing out of order: a thread with a new reply could stay on top after the server caught up, above rows with newer activity, so older rows (such as "25m" or "1h") showed above "now" rows. Activity is now always ordered by latest activity, newest first.
- Fixed agent status in lists: an agent in Home direct messages or the member list no longer stays "Online" while it is working, where only opening the agent showed "Working". Agent status also refreshes right away after switching to another server.
- An agent without an avatar now shows the default pixel robot everywhere, never its initials or the person icon, and so does an agent whose avatar image fails to load. A person without an avatar, or whose avatar fails to load, shows the person placeholder everywhere instead of their initials, as on the web. The other side of an agent's DMs now shows as an agent, and people without an avatar no longer get a made-up pixel avatar in search results; an external (for example Slack) sender without a picture shows their initials, as on the web.
- The upload status on attachments waiting above the message box no longer spills out: "Finishing upload…", "Checking file…", "Upload failed" and the other labels stay inside the image tile, wrapping or ending in "…" when they don't fit, instead of being cut off at the screen edge or covering what's next to them. While an upload finishes, its bar now sweeps to show it is waiting for the server to confirm.
- On a Computer's page, an agent in "Agents on this computer" that has no avatar of its own now shows the default pixel avatar, as on the web, instead of its initial.
- Long-pressing a link in a message now opens that message's menu (it did nothing before), with a section for the link on top: the link's address on one line, then Open, Copy link and Share, plus Open in browser for links outside Raft. Open takes a Raft link straight to it in the app. Long-pressing an @mention, channel or task chip opens the message menu too. Tapping a link still opens it.
- Replying in a thread in an agent's Lounge no longer gets stuck on "Checking permissions - sending is temporarily unavailable". As on the web, you can reply in a Lounge's threads right away (unless the Lounge is read-only for you or archived). If a thread's send permission still can't be confirmed after a few seconds, the app now asks the server directly instead of waiting forever.
- An @name inside a quote (lines starting with `>`) now shows as plain text instead of a mention, and quoting someone's message in a reply no longer mentions the people it names again. An @ you write after the quote is still a mention.
- If someone removes you from a channel while you have it open, the app now closes the channel with "You're no longer in this channel" and drops its rows from Activity, instead of staying on it and retrying to load new messages.
- An agent's Report Issue form now says the report is sent to the Raft team, instead of wrongly saying everyone in the workspace can read it. The extra notes under Include are gone, so the form is shorter.
- Fixed the Saved label under a message not responding to taps. As on the web, tapping it now removes the message from Saved.
- In a task's conversation, when you haven't joined the task's channel, Join channel takes the composer's place. It always failed with "Unable to join channel"; it now joins the task's channel, and the composer appears so you can reply.
- The reply count under "Beginning of conversation" at the top of a thread no longer says "0 replies" above replies you can see. It now counts the same way as the thread header: when the original message's count hasn't caught up yet, the replies you can see are counted, and nothing is shown while the replies are still loading.
- Links in messages that end in `_` (such as share links) now open in full instead of losing the trailing `_`, and a lone `_` no longer shows as `*`.
- A number like `#4442` in a message that isn't a known task of the conversation now shows as plain text, as on the web, instead of a tappable tag that only said it couldn't be opened. `#7` opens task 7 of the current conversation only; the app no longer searches other channels for a task with that number or asks you to pick one. In a task's conversation, `#7` is task 7 of the task's channel, and these task tags also show when you can only read the conversation.
